## Confirmed defect and correction

The duplicate fold-marker key can cause a visible duplicate context line. A development-React component fixture rendered ten context lines, then selected **split → unfold → fold → expand → unified**. Before the fix, the final content contained `context-0` twice. The fold marker and first retained row both used the same numeric row ID.

`src/DiffViewer.tsx` now includes row kind in unified-row and shared split-row React keys. The parsing model, original diff, line numbers and expansion IDs remain unchanged. The regression checks exact final context content and absence of duplicate-key warnings. It failed before the fix and passed afterward; the existing paired-word/split-context test also passed.

## Office editing boundary

Office layout previews are read-only. This work does not add or claim DOCX/XLSX/PPTX editing, save-back, formula calculation, complete pagination, or complex slide/master fidelity. CSV/TSV retain the explicit **edit as text** handoff in `Inspector.tsx`; that path opens the existing original-text editor via `workspace.read`, rather than writing the clipped layout model. The existing `CSV layout preview keeps the existing original-text editor available` regression and the production handoff were inspected, not mechanically rerun. Existing editor truncation/conflict/save protections remain outside this content-only change.
