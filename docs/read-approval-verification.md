# Conservative read approval

Verified on 2026-10-05 against the configured official CLI **grok 1.0.46 (2765805b9442)**. An initial probe of the older PATH installation, 1.0.13, returned the same shapes; the support decision uses the configured 1.0.46 result.

`node scripts/verify-cli-read-policy.cjs <official-grok.exe>` uses a newly created profile, GROK_HOME, project and temporary directory, an environment-variable allowlist, and a deterministic HTTP/SSE model on 127.0.0.1. The only model credential is a fixed fake fixture key. It never reads or copies the real CLI's authentication/configuration files. All four permission requests are cancelled, including the shell request. No paid inference or real prompts are used. The report records no external proxy requests; this is evidence for the fixture, not a claim of an OS network sandbox. The owned CLI, local server and temporary directories were cleaned up. Raw results are in the ignored `test-results/cli-read-policy.json`.

The committed `tests/fixtures/official-read-permissions.json` contains the actual synthetic tool-call bodies, with no user paths or session text. Each successful classifier requires `_meta["x.ai/tool"]` version 1, namespace `grok_build`, `read_only: true`, the exact identity below, and matching raw/canonical input. Display titles and labels never grant permission.

| Built-in name | Canonical kind | ACP kind | Raw variant | Canonical/raw target                                                    |
| ------------- | -------------- | -------- | ----------- | ----------------------------------------------------------------------- |
| `read_file`   | `read`         | `read`   | `ReadFile`  | `input.path` = `rawInput.target_file`                                   |
| `grep`        | `search`       | `search` | `Grep`      | `input.path` = `rawInput.path`, or omitted for cwd; patterns must match |
| `list_dir`    | `list`         | `other`  | `ListDir`   | `input.directory` = `rawInput.target_directory`                         |

The official [normalization implementation](https://github.com/xai-org/grok-build/blob/2bdd1d6a6369de0e8c68132ea4539e9abd9e14a8/crates/codegen/xai-grok-tools/src/normalization.rs) resolves identity from registered tool metadata and projects typed input. Its [metadata schema](https://github.com/xai-org/grok-build/blob/2bdd1d6a6369de0e8c68132ea4539e9abd9e14a8/crates/codegen/xai-grok-tools/schema/tool_meta.schema.json) distinguishes built-in namespaces from `mcp`. The [permission request implementation](https://github.com/xai-org/grok-build/blob/2bdd1d6a6369de0e8c68132ea4539e9abd9e14a8/crates/codegen/xai-grok-shell/src/session/acp_session_impl/tool_calls.rs#L1762) stamps this metadata into the actual reverse request. Standard ACP [name/kind metadata](https://agentclientprotocol.com/protocol/v1/tool-calls) describes presentation and is insufficient by itself.

`read` applies only to permission requests that reach Desktop. The CLI may already allow read-only tools under its existing rules. Desktop keeps `autoMode` and `yoloMode` false and selects only an existing official `allow_once` option. Unknown, custom, MCP, shell (including `echo`/`cat`), write/delete, incomplete or conflicting requests still ask. Unsupported namespaces/versions, unavailable one-time choices and inaccessible/unapproved paths also ask; no names are guessed.

The verified grep runner does not pass `--follow` by default. It does honor a nonempty `RIPGREP_CONFIG_PATH`, whose configuration can change traversal or run preprocessors. Desktop therefore keeps grep requests manual when that environment setting exists, without reading the configuration. See the pinned [runner](https://github.com/xai-org/grok-build/blob/2bdd1d6a6369de0e8c68132ea4539e9abd9e14a8/crates/codegen/xai-grok-tools/src/implementations/grok_build/grep/rg_runner.rs) and [configuration-aware dispatch](https://github.com/xai-org/grok-build/blob/2bdd1d6a6369de0e8c68132ea4539e9abd9e14a8/crates/codegen/xai-grok-tools/src/implementations/grok_build/grep/offer.rs).

`GrokClient` accepts `authorizeRead({ cwd, paths })`, where paths are absolute. Its default checks real paths against the project root. The application may supply its existing access grant check for explicitly authorized attachments. External paths and directory links out of the project require that explicit grant. Pending path checks cannot answer after cancellation, turn completion, a mode change away from read, a manual response or request ID reuse. Reloading a known session preserves its mode; a disconnected client defaults to ask until its owner restores the saved choice.

Candidate reads wait for path authorization before publishing an approval event. A verified automatic approval therefore opens no permission dialog and sends no approval notification; denied or unavailable scope checks and mode changes fall back to the normal prompt. If stdin closes while authorization is pending, the resulting write error follows the connection-failure lifecycle instead of becoming an unhandled rejection.

Focused validation: the initial ACP/read-policy/permission-dialog run passed 60 tests. After the runtime and review fixes, `node --test tests/acp.test.cjs tests/read-approval.test.cjs tests/session-runtime.test.cjs tests/session-hub.test.cjs` passed 96 tests. New tests first failed for the missing `read` mode, custom ripgrep configuration, automatic read approval notifications, and background controls incorrectly marked as finishing. The checks cover realpath containment, a directory link leaving the project, synthetic malicious identity/parameter conflicts, manual fallbacks, late-response races and closed stdin. Existing ask/auto and option-ID/cancellation tests remain green. No full suite, release, commit or user CLI session was run by this probe.

`tests/e2e-architecture.cjs` additionally uses the real Electron/main/preload/ACP path with isolated local fixture data. It covers built-in read auto approval, shell prompts, one selected-session restore after terminating the actual owned fixture child, failure without a retry loop, unchanged drafts/read mode, interrupted queues remaining paused, manual recovery with automatic recovery disabled, and foreground workflow controls while the parent task remains in the background. The main task snapshot drives busy/stop/queue availability; local send preparation and streaming turn identity remain local. Automatic recovery never sends a prompt, resumes a queue or restarts all session processes. Its per-target attempt budget resets only for explicit user activity.
