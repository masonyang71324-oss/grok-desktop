## Finding — resolved

**P2 — Always stop the owned CLI when temporary-session deletion fails.** In `scripts/verify-live-session.cjs:125-129`, the cleanup `deleteSession` is awaited before `stop(client)`. A rejected deletion RPC exits the `finally` block before disposal. The script then only assigns `process.exitCode`; the still-running CLI and its pipes can keep the probe alive and leave the owned process behind. `_x.ai/session/delete` errors do not themselves force the ACP transport closed.

Reproduction used the script unchanged in an in-memory VM with a fake client and fake filesystem: creation succeeded, a normal operation failed, then the cleanup delete RPC rejected. Recorded calls were `newSession`, `deleteSession`, and the outer failure message; `disposeCalled` was `false`. No real process or session was created. Use an inner `try/finally` so `stop(client)` is unconditional. Keep the temporary cwd when deletion is unconfirmed, and report that cleanup failure without claiming the session was removed.

**Resolution rechecked on 2026-10-03:** the cleanup deletion now has an enclosing `finally` that always invokes `stop(client)`. A further `finally` removes the temporary cwd only when deletion was confirmed or no session ID was obtained. A rejected deletion therefore still disposes the owned client, preserves the failed-deletion workspace, and rejects the probe instead of writing a success report. The `require.main` guard prevents imported verification from running automatically. Reviewed `tests/live-cli-probes.test.cjs`: it executes the actual verifier source with fake CLI/filesystem boundaries and asserts both disposal and workspace retention after the deletion error. The integration owner reported the regression failing before this fix and passing afterward; this narrow recheck did not repeat that already-passed test or call the real CLI. No issue remains from this finding.
