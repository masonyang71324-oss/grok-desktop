# Architecture and reliability improvements

Approved scope: the five architectural directions confirmed by the user on 2026-10-05. Baseline 1.9.0 / d6b2a08. Preserve stable, simple, bilingual operation and existing data. No framework/agent rewrite or speculative PID cleanup.

1. **Checkpoint content deduplication.** Keep full supported-file reads and coverage/restore semantics; do not trust mtime+size as content identity. Store repeated UTF-8 content once in content-addressed blobs (hashing replaces duplicate disk storage). New manifests reference blobs; legacy inline records remain readable and restorable without destructive migration. Atomic writes precede references, and unreferenced cleanup must never remove content required by a surviving/active/undo record. Keep the existing capacity choices and account for physical shared storage.
2. **Crash lifecycle.** First probe the current Utility Process terminal and npm runner using only owned isolated processes, killing the owned desktop main process rather than its whole tree. If real descendants survive, implement narrowly owned lifetime supervision appropriate to Windows, with no boot-time killing based on old PID files. Explicit external user terminals keep their independent lifetime. Do not claim all OS/process types are covered by one fixture.
3. **Authoritative runtime and diagnostic export.** Gradually derive visible task activity and action availability from the main-process snapshot, retaining local send preparation and stream identity. Export an immutable, previewed diagnostic ZIP containing whitelisted versions/settings, counts and sanitized operational events. Never read/include prompts, attachments, session text, full paths, credentials, arbitrary error bodies or memory dumps; no automatic upload.
4. **Conservative read approval and reconnect.** Add `read` beside `ask`/`auto`. Verify the official CLI/ACP read-tool shape; only proven read/search built-ins with matching structured data may use an official `allow_once`. Shell execution, MCP/custom/unknown/contradictory tools continue to ask. If available protocol evidence cannot distinguish them, keep asking and explain the boundary. Automatically attempt one selected-session/catalog restoration after an unexpected disconnect, preserve permission/trust and drafts, pause interrupted work, never resend prompts or resume queues automatically. Manual action can rearm recovery; failed automatic recovery must not loop.
5. **Stable/beta channels and staged delivery.** Stable remains default; beta is explicit opt-in. Honor semantic versions and refuse automatic downgrades. Channel changes cannot reuse an installer or response from another in-flight channel. Installed-app staged distribution uses electron-updater metadata; initial percentage defaults to 100 and publisher controls can change it. Provide a GitHub Actions operation that adjusts only the selected release manifest's percentage, without rebuilding/replacing installer bytes. Portable updates offer the selected channel's download page.

Verification focuses on legacy/new restore and shared-blob deletion, actual owned-process main-crash behavior, adversarial synthetic secret exclusion in previews/exports, interrupted prompts/queues never being replayed, conservative permission fallbacks, and channel/rollout compatibility. Tests use isolated data and local/mock models; no real credentials, paid prompts or unrelated processes are touched. Publish and install the verified public artifact using the previously authorized release workflow after checking that the installed app is idle.
