# 1.8.0 审阅建议补全

用户要求继续完成先前后置的代码工作，保持稳定、简单、不削减功能。基线 1.7.4 / 46295bf。

## 实施范围

1. 历史相邻文本分片合并、线性回放、帧级批量更新；对话和会话列表按需渲染，保留全文、轮次、附件、权限与当前回合索引，搜索定位和有意选择/复制必须完整。性能采用可重跑合成夹具，不能把本机数字当所有机器保证。
2. 检查点轻量索引兼容旧记录，正文仍是恢复依据，损坏索引可重建；摘要与空记录筛选不删除证据。项目日志改增量并处理启动快照与迟到事件。附件只管理应用自有截图目录，显式确认删除，保护草稿/排队/运行引用；旧会话可能受影响必须提示。
3. Windows 短暂文件占用做有界重试，等待期间再次检查外部修改。命令超时与输出超限清理自有进程树；引擎更新失败后只做本地版本健康检查并给出恢复指引，不自动重试更新，不宣称证明上游更新原子性。
4. PTY 迁至 Utility Process，关闭 RunAsNode/NODE_OPTIONS，启用 ASAR 完整性及只从 ASAR 加载。保留用于真实打包版 Playwright 检查的主进程调试 fuse，明确此边界；不是未做任何 Fuses 加固。
5. 主进程检查所有 IPC 参数结构，登记项目/本机原生选择的文件；任意渲染器路径不能直接读写。原生文件对象的拖放登记通过不向公开 request 列表暴露的 preload 通道完成。历史草稿的附件授权由主进程保存，不能经 settings.save 伪造。
6. 新项目可先只看文件，信任后才能修改文件、运行终端/脚本或启动 Grok 项目会话。1.7.4 以前已选择的项目保留既有使用权限；明确保存的只读状态不被覆盖。更改信任前保护运行任务、队列和终端。项目信任约束桌面入口，不冒充 Grok 工具的操作系统沙箱。
7. 全 electron 模块 checkJs 与实用 ESLint 纳入检查；按职责提取 App 会话列表、引擎面板/hook，保留交互。Actions 固定官方发布提交；历史文档归档并修正链接。
8. 准备真实代码签名的构建入口和说明。没有发布者证书或签名服务凭据时仍准确标记未签名，不申请/购买证书，不修改许可证，不伪造签名。
